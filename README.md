# قُرآن | QURAN

## تحديثات واجهة القراءة (أحدث نسخة)

- **إصلاح جذري**: دائرة رقم الآية كانت تفشل في توسيط الرقم بصريًا (وتبدو وكأن الرقم "يخرج" عن الدائرة) بسبب تعارض CSS حقيقي — فئة `.tabular-ltr` كانت تفرض `display: inline-block` على نفس العنصر الذي يحمل أيضًا `inline-flex` من Tailwind، فتُلغى خاصية التوسيط الفعلية. تم حذف `display` من `.tabular-ltr` نهائيًا، واستُبدلت الدائرة بفئة `.ayah-badge` مبنية بوحدات `em` نسبية لحجم الخط، مع `min-width` بدل عرض ثابت — فلا تنكسر حتى مع أرقام من 3 خانات مثل آية 286 في سورة البقرة (تم التحقق فعليًا من هذه الحالة تحديدًا).
- **إعادة توزيع الأزرار**: أُزيل زر "التفسير" من أسفل كل آية (يتكرر 6236 مرة سابقًا)، وانتقل إلى الشريط العلوي لصفحة السورة (بجانب خيارات القراءة)، ويفتح تفسير **الآية الحالية المعروضة فعليًا** على الشاشة. أُضيف زر "استمع" جديد في الشريط العلوي يفتح قائمة منسدلة باختيار القارئ لتشغيل السورة كاملة (مشغّل صوتي عائم بتصميم زجاجي). بقي زر "حفظ علامة" فقط أسفل كل آية لأنه إجراء خاص بالآية بطبيعته.
- **خلفية داكنة لصفحة القراءة فقط**: أُضيف خيار خلفية جديد ("داكنة مريحة ليلاً") ضمن خيارات خلفية القراءة الموجودة أصلًا. **هذا مختلف عن الوضع الداكن العام للتطبيق** المحظور صراحة في النسخة الأولى من المواصفات (القسم 3.1) — شريط التنقل والبطاقات والإعدادات وبقية الواجهة تبقى فاتحة كما هي دائمًا؛ فقط "ورقة" صفحة القراءة نفسها (نص الآيات) يمكن أن تصبح داكنة، تمامًا كخاصية "وضع الليل" في تطبيقات القراءة الإلكترونية (Kindle وغيرها)، وليست تبديلًا لهوية التطبيق البصرية.
- **الألوان والزجاجية**: أُضيفت فئة `.glass-btn` وطُبِّقت على الأزرار الثانوية والعناصر التفاعلية (أزرار الرجوع، التنقل بين الصفحات، تحديد الموقع، إلخ) في مختلف الصفحات؛ الأزرار الرئيسية ذات الإجراء الحاسم (مثل "بدء جلسة الاسترخاء") بقيت بلون صلب عمدًا لوضوح التباين. خلفية التطبيق العامة تحوّلت من أبيض نقي صرف إلى أبيض باهت جدًا مائل للرمادي الأزرق (`#f6f9fc`) لراحة أكبر للعين، مع إبقاء البطاقات والعناصر البارزة بيضاء/زجاجية فوقها.

## 2. التشغيل والبناء والنشر

```bash
# تثبيت الاعتماديات
npm install

# توليد بيانات التطبيق (نص القرآن + التفسير + فهرس البحث) من المصادر الخام
# يُنفَّذ تلقائيًا إن لم تُعدِّل مصادر البيانات؛ أعد تشغيله فقط إذا غيّرت
# الملفات في data-src/ (راجع القسم 4 أدناه)
node --experimental-strip-types scripts/build-data.mts

# وضع التطوير
npm run dev

# الاختبارات
npm test              # أو: npx vitest run

# فحص الأنواع (TypeScript strict)
npx tsc -b --noEmit

# البناء للإنتاج (ينتج مجلد dist/ قابل للنشر على أي استضافة ثابتة تدعم HTTPS)
npm run build

# معاينة البناء محليًا
npm run preview
```

**النشر**: `dist/` هو مجلد ثابت بالكامل (Static). انشره على أي استضافة تدعم HTTPS (Cloudflare Pages، Netlify، Vercel، GitHub Pages، أو أي خادم ويب عادي). **يجب أن يكون الموقع على HTTPS** (أو `localhost` أثناء التطوير) لكي يعمل Service Worker والتثبيت كـ PWA؛ هذا قيد من المتصفحات نفسها وليس خيارًا في التطبيق.

**إضافة بيانات جديدة لاحقًا** (مثل تفسير إضافي): أضف الملفات الخام إلى `data-src/`، عدّل `scripts/build-data.mts` ليقرأها، ثم أعد تشغيله والبناء.

> **ملاحظة**: مجلد `data-src/` (البيانات الخام قبل المعالجة) **غير مُضمَّن** في هذه الحزمة المُسلَّمة عمدًا — حجمه ~77 ميجابايت ومعظمه ملفات وسيطة غير مُستخدَمة (نسخ خطوط كاملة، إصدارات تفاسير أخرى لم تُستخدَم). **التطبيق يعمل بكامل وظائفه بدون هذا المجلد** لأن `public/data/` (الناتج المُعالَج) موجود بالفعل ومُضمَّن. تحتاج `data-src/` فقط إذا أردت **إعادة توليد** `public/data/` من جديد (مثلًا لإضافة تفسير آخر) — إليك كيفية إعادة إنشائه:

```bash
mkdir -p data-src && cd data-src

# 1) نص القرآن (تنزيل) + بيانات السور، عبر مرآة risan/quran-json
curl -sL https://codeload.github.com/risan/quran-json/tar.gz/refs/heads/main -o r.tar.gz
tar -xzf r.tar.gz quran-json-main/data/tanzil/chapters.json \
                   quran-json-main/data/tanzil/uthmani.json \
                   quran-json-main/data/tanzil/simple-clean.json

# 2) التفسير الميسّر (114 ملفًا، واحد لكل سورة) من spa5k/tafsir_api
mkdir -p tafsir-muyassar
for i in $(seq 1 114); do
  curl -s "https://raw.githubusercontent.com/spa5k/tafsir_api/main/tafsir/ar-tafsir-muyassar/$i.json" \
    -o "tafsir-muyassar/$i.json"
done

cd .. && npm run build:data   # يقرأ من ./data-src بجانب المشروع تلقائيًا
```

(يمكن أيضًا تمرير مسار مختلف عبر `QURAN_DATA_SRC=/path/to/data-src npm run build:data`.)

- **لا اعتماد على مصدر واحد فقط عمليًا**: القائمة تضم 5 قرّاء مختلفين؛ عند فشل مقطع يقترح التطبيق المحاولة من جديد، والمستخدم يمكنه اختيار قارئ آخر يدويًا.

## 4. محرك البحث العربي — القرار الهندسي والتحديات الحقيقية

هذا الجزء هو الأكثر دقة تقنيًا في المشروع، ويستحق شرحًا صادقًا لأنني اكتشفت وأصلحت خللين حقيقيين أثناء البناء (وليس نظريًا فقط):

### 4.1 لماذا لا يُبنى البحث مباشرة من نص المصحف العثماني؟
النص العثماني يستخدم "الألف الخنجرية" (ٰ) لكتابة صوت الألف الممدود في بعض الكلمات بلا حرف ألف ظاهر. المشكلة: هذا الرمز **غامض لغويًا** — أحيانًا يقابله ألف مكتوبة في الإملاء القياسي (مثل: `ٱلْعَٰلَمِينَ` ⟵⟶ `العالمين`)، وأحيانًا **لا** يقابله ألف أصلًا لأن الكلمة مرسومة إملائيًا بالحذف حتى في الإملاء الحديث (مثل: `ٱلرَّحْمَٰنِ` ⟵⟶ `الرحمن` بلا ألف). لا توجد قاعدة حرفية واحدة تحل الحالتين معًا.

**الحل المُنفَّذ**: يُبنى فهرس البحث من **النص القياسي المبسّط** (`simple-clean` من مشروع تنزيل نفسه)، بينما يبقى **المعروض للمستخدم دائمًا هو النص العثماني الكامل التشكيل**. هذا يعني أن البحث يطابق ما يكتبه المستخدم فعليًا بدقة، والنتيجة المعروضة أصيلة 100%.

### 4.2 الربط بين النصّين للتمييز البصري
لتمييز الكلمة المطابقة في النص العثماني المعروض (وهذا مطلب صريح في المواصفات)، بُنيت خوارزمية **محاذاة على مستوى الكلمة** وقت البناء (`scripts/build-data.mts`)، تتعامل مع الفروقات البنيوية المعروفة بين النصّين، أهمها:
- حرف النداء "يا" يُكتب مدمجًا مع الكلمة التالية في الرسم العثماني (مثال: `يَٰٓأَيُّهَا` = "يا" + "أيها").
- عدد صغير من الكلمات (الصلاة، الزكاة، الحياة...) يُكتب فيها صوت الألف الممدود بواو + ألف خنجرية بدل الألف المعتادة.

**النتيجة المُقاسة فعليًا على كامل النص (6236 آية، 78248 كلمة)**: **98.96%** من الكلمات تُحاذى بثقة كاملة عبر قواعد مطابقة صريحة. الـ 1.04% المتبقية (812 كلمة ضمن 486 آية) تستخدم محاذاة احتياطية بالموضع — وهذا **لا يعني أبدًا نتيجة بحث خاطئة** (الآية تظل تُعاد بشكل صحيح دائمًا)، بل فقط أن تمييز الكلمة المطابقة بصريًا قد لا يكون دقيقًا بنسبة ضئيلة من الحالات النادرة. هذا الرقم مُسجَّل تلقائيًا في مخرجات `scripts/build-data.mts` عند كل بناء، وليس ادعاءً غير موثّق.

### 4.3 اختباران حقيقيان اكتشفا هذين الخللين
- اختبار `does not create misleading matches by over-normalizing` في `arabicNormalize.test.ts`.
- اختبار الانحدار الخاص بالألف الخنجرية (موثّق بالتعليقات في `arabicNormalize.ts`).
هذان الاختباران جزء من مجموعة الاختبارات الدائمة، فإن حاول أحد لاحقًا "تبسيط" المعالجة سيفشل البناء.

### 4.4 الأداء
البيانات صغيرة بما يكفي (6236 آية) لجعل **المسح الخطي على النص المُطبَّع المُحسوب مسبقًا وقت البناء** أسرع من حاجة أي فهرس عكسي معقّد — قياس فعلي ضمن الاختبارات: بحث عبر نسخة اصطناعية من الفهرس الكامل (6236 مُدخلًا) يستغرق أقل من 100 مللي ثانية (الاختبار `measures search time is fast` في `searchEngine.test.ts`). يعمل البحث داخل Web Worker منفصل عن الواجهة حتى لا يتجمّد أثناء الكتابة، ودون أي Debounce مصطنع لأن الفهرس أسرع من حاجته أصلًا.

### 4.5 سياسة تطبيع النص (موثّقة بالكامل كتعليقات في `src/lib/arabicNormalize.ts`)
إزالة التشكيل، توحيد أشكال الألف (أ/إ/آ/ٱ ⟵ ا)، توحيد الألف المقصورة مع الياء، توحيد التاء المربوطة مع الهاء، إزالة التطويل. **لا تحويل جذري أو اشتقاق للجذور** — تحديدًا لتفادي مطابقات مضلّلة (مُختبَر صراحة أن "كتب" و"كتاب" تبقيان مختلفتين بعد التطبيع).

## 5. العمل دون إنترنت (Offline-First)

- **Service Worker** (عبر vite-plugin-pwa / Workbox) يخزّن مسبقًا (precache) عند التثبيت: هيكل التطبيق كاملًا، **كل** ملفات نص القرآن (114 ملفًا)، **كل** ملفات التفسير (114 ملفًا)، فهرس البحث الكامل، الخطوط، والأيقونات — إجمالي ~8.9 ميجابايت مضغوطة جزئيًا ضمن 272 ملفًا (تم التحقق من هذا الرقم فعليًا عبر بناء إنتاجي حقيقي).
- **قرار هندسي**: بما أن الحجم الإجمالي معتدل (ليس مئات الميجابايتات)، اختير تخزين كل البيانات دفعة واحدة عند التثبيت بدل تنزيل تدريجي معقّد — هذا يضمن أن "القراءة + البحث + التفسير" تعمل دون إنترنت فور اكتمال التثبيت الأول، لا بعد زيارة كل سورة على حدة.
- **لا يُخزَّن خطأ شبكة أبدًا كمحتوى صالح**: إعداد Workbox يحدد `cacheableResponse: { statuses: [200] }` صراحة.
- **مؤشر صادق لحالة الجاهزية دون إنترنت**: صفحة الإعدادات تتحقق فعليًا (عبر Cache API، وليس افتراضًا) من وجود `search-index.json` في الذاكرة المؤقتة قبل أن تُخبر المستخدم أن التطبيق "جاهز للعمل دون إنترنت".
- **سياسة تحديث آمنة**: `registerType: "prompt"` (وليس `autoUpdate`) — لا يُستبدَل كود التطبيق تحت المستخدم أثناء الجلسة؛ تظهر بانر صريح "يتوفر تحديث" وينتظر تأكيد المستخدم (`src/app/UpdatePrompt.tsx`).
- **ما يعمل فعليًا دون إنترنت** (بعد التثبيت الأول): فتح التطبيق، قائمة السور، القراءة (وضعا التمرير والصفحات)، البحث، التفسير، العلامات المرجعية، إعدادات القراءة، **ومواقيت الصلاة** (الحساب محلي بالكامل بمجرد اختيار مدينة أو تحديد الموقع مرة واحدة).
- **ما يحتاج إنترنت دائمًا**: **وضع الراحة والاستماع فقط** — موضّح بصريًا في الصفحة نفسها، ولا تظهر رسالة خطأ عامة لبقية التطبيق بسبب انقطاع الاتصال.

## 6. التخزين المحلي — التوزيع حسب المواصفات

| النوع | أين | لماذا |
|---|---|---|
| العلامات المرجعية | IndexedDB (`src/lib/db.ts`) | بيانات مستخدم تراكمية |
| آخر موضع قراءة | IndexedDB (`src/lib/db.ts`) | — |
| إعدادات القراءة (حجم الخط، الخلفية، نمط القراءة) | localStorage (`src/lib/settings.ts`) | إعداد صغير |
| إعدادات مواقيت الصلاة (المدينة، طريقة الحساب، المذهب) | localStorage (`src/lib/settings.ts`) | إعداد صغير |
| نص القرآن، التفسير، فهرس البحث | ملفات ثابتة مخزَّنة عبر Service Worker (Cache API) | بيانات كبيرة للقراءة فقط، لا تحتاج معاملات IndexedDB |

جميع عمليات IndexedDB وlocalStorage مُغلَّفة بـ `try/catch` وتُعيد قيمًا آمنة عند الفشل بدل تعطّل التطبيق (راجع `db.ts` و`settings.ts`).

## 9. قيود معروفة (بصدق تام)

1. **رابط الصوت في وضع الراحة لم يُختبَر فعليًا** من بيئة البناء (راجع القسم 3.5) — يحتاج تحققًا يدويًا بعد النشر.
2. **قائمة مدن مواقيت الصلاة غير شاملة** (~48 مدينة) — أي مدينة أخرى تحتاج تحديد الموقع الجغرافي يدويًا.
3. **ترقيم "الصفحات" في وضع القراءة صفحة-بصفحة داخلي** (10 آيات لكل صفحة تقريبًا)، **وليس مطابقًا لترقيم صفحات المصحف المطبوع الرسمي ذي الـ604 صفحة** — هذا موضّح للمستخدم مباشرة داخل الواجهة، وليس ادعاءً مخفيًا.
4. **تصنيف "مكية/مدنية"** لكل سورة منقول حرفيًا من بيانات مشروع تنزيل الرسمية؛ بعض السور (كالفلق والناس) محل اختلاف علمي معروف بين المصادر، وهذا التطبيق يعرض تصنيف تنزيل تحديدًا دون ادّعاء إجماع.
5. **محاذاة التمييز البصري للبحث دقيقة بنسبة 98.96%** (راجع القسم 4.2) — النسبة المتبقية لا تؤثر على صحة نتيجة البحث نفسها، فقط على دقة تظليل الكلمة.
6. **لم يُختبَر التثبيت الفعلي كتطبيق PWA على جهاز حقيقي** ضمن هذه الجلسة (راجع 8.1).
7. **مواقيت الصلاة حساب فلكي قياسي محلي، وليست مطابقة رسميًا** لأي جهة حكومية بعينها — موضّح هذا نصًا داخل صفحة المواقيت نفسها.

```
src/
  app/            تخطيط التطبيق، التوجيه، بانر التحديث
  components/     مكونات مشتركة (بطاقات زجاجية، شريط تنقل، حالات التحميل/الخطأ)
  features/
    home/         الصفحة الرئيسية
    quran/        قائمة السور، واجهة القراءة، عرض الآية، شريط أدوات القراءة
    search/       صفحة البحث
    tafsir/       صفحة التفسير
    prayer-times/ صفحة المواقيت + منطق الحساب (prayerLib.ts + اختباراته)
    relaxation/   وضع الراحة والاستماع
    settings/     الإعدادات والعلامات المرجعية ومصادر البيانات
  lib/            منطق مشترك: التطبيع العربي، محرك البحث، IndexedDB، الإعدادات،
                  بيانات المدن، القرّاء، تحميل البيانات، الأنواع المشتركة
  workers/        Web Worker الخاص بالبحث
  hooks/          useQuranSearch، useBookmarks، useLastPosition، useOnlineStatus
scripts/
  build-data.mts  معالجة البيانات الخام + كل عمليات التحقق من السلامة
public/
  data/           بيانات القرآن والتفسير وفهرس البحث (JSON) — مُولَّدة، لا تُعدَّل يدويًا
  fonts/          AmiriQuran، Noto Naskh Arabic + ملفات تراخيص OFL
  icons/          أيقونات PWA بمقاسات متعددة + نسخ قابلة للقص (maskable)
```

## 11. المبدأ الذي التُزم به
